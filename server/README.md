# Сервер MAX Upgrader

Fastify + Postgres. Первый этап: аккаунты, облачный прогресс,
цепочка честности. Экономика игр переезжает сюда следующим этапом.

## Локально

```bash
npm install
# нужен Postgres на 5432 и .env с DATABASE_URL и JWT_SECRET
npx prisma db push
npm run dev
npm test          # поднимает сервер и бьёт в реальный HTTP
```

## На сервере

```bash
cd ~/max-upgrader-server
docker compose up -d --build
```

`.env` создаётся автоматически при первом деплое: пароль базы и
JWT-секрет генерируются на месте и в репозиторий не попадают.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | проверка живости, дёргает базу |
| POST | `/auth/register` | регистрация, сразу отдаёт пару токенов |
| POST | `/auth/login` | вход |
| POST | `/auth/refresh` | обмен refresh на новую пару, старый гасится |
| POST | `/auth/logout` | отзыв refresh |
| GET | `/me` | профиль, инвентарь, текущий хэш сида |
| POST | `/me/import` | разовый перенос локального сохранения |
| POST | `/me/seed` | смена цепочки, старый сид раскрывается |

Access живёт 15 минут, refresh — 60 дней и одноразовый: при обмене
старый сразу гасится, поэтому украденный токен переживает максимум
один запрос.

## Что уже защищено

- Пароли через argon2id.
- Ответ на «нет такого логина» и «неверный пароль» одинаковый —
  перебором логины не собрать.
- Перенос прогресса разрешён один раз и только пока на сервере нет
  сыгранных раундов, иначе импортом можно было бы затирать проигрыши.
- Ограничение частоты запросов: 120 в минуту на IP.
- Баланс в BigInt: предметы доходят до 6.8 млн, а выдачи из админки
  легко выходят за 32 бита.
